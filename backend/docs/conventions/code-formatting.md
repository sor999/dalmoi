# 코드 형식 자동화

## 로컬 실행

Java 25를 사용하며 다음 명령은 `backend/`에서 실행한다.

```sh
./gradlew spotlessApply
./gradlew spotlessCheck checkstyleMain checkstyleTest
```

Spotless 8.11.0과 Eclipse JDT 4.37 프로필을 사용한다. 네 칸 들여쓰기, 필드·메서드 사이 빈 줄, 필드 애너테이션 별도 줄, 120자 기준 긴 호출 줄바꿈을 적용한다. 짧은 `throws`와 첫 인자는 가능한 한 기존 선언·호출과 같은 줄에 둔다. 프로덕션·테스트·Fixture를 모두 대상으로 하며 README는 변경하지 않는다.

Checkstyle 13.9.0은 필드 애너테이션 위치, 선언 사이 빈 줄, 탭, 괄호 주변 공백, 중괄호 및 한 줄의 다중 문장 등을 검사한다. 의미 단위별 본문 빈 줄은 리뷰로 확인한다.

## 커밋 훅 설치

최초 체크아웃 후 저장소 루트에서 다음 명령을 실행한다.

```sh
./scripts/install-git-hooks.sh
```

Git의 로컬 `core.hooksPath`를 `.githooks`로 설정한다. 기존에 다른 훅 경로가 지정되어 있으면 덮어쓰지 않고 설치를 중단한다. 훅 설치는 clone 시 자동 전파되지 않으므로 개발 환경마다 한 번 실행한다.

`pre-commit`은 백엔드 코드·빌드·검사 설정에 스테이징 변경이 있을 때 인덱스 전체를 임시 폴더로 내보내 동일한 형식 검사를 실행한다. 작업 파일을 고치거나 자동 스테이징하지 않는다. 부분 스테이징 중 작업 파일만 고쳐도 인덱스에 오류가 남아 있으면 커밋을 차단한다.

실패하면 `spotlessApply` 실행 후 필요한 변경을 검토하여 다시 스테이징한다. 문서만 변경한 커밋은 검사 대상에서 제외한다.

## CI

`.github/workflows/backend-style.yml`이 `dev`·`main` 대상 PR과 해당 브랜치 push에서 `spotlessCheck checkstyleMain checkstyleTest`를 실행한다. 형식 검사에는 DB 컨테이너가 필요하지 않다. GitHub에서 머지 필수 조건으로 강제하려면 브랜치 규칙에 `Backend style / style` 검사를 필수로 등록한다. 워크플로 추가만으로 저장소 보호 규칙이 자동 변경되지는 않는다.

## 설정 변경 검증

`python3 backend/scripts/test-formatter.py`를 저장소 루트에서 실행한다. 임시 프로젝트에서 실제 포매터를 두 번 실행하여 이넘 항목, 빌더 체인, 애너테이션, throws 및 첫 인자 배치와 반복 안정성을 확인한다. CI에서도 동일하게 실행한다.

이넘은 항목별 한 줄, 빌더는 설정 호출별 줄바꿈을 유지하며 기존의 의도적인 줄바꿈을 자동으로 합치지 않는다.

- 필드 애너테이션을 같은 줄에 두면 검사 실패
- 필드 사이 빈 줄을 없애면 검사 실패
- 잘못된 들여쓰기를 `spotlessApply`가 복원
- 형식이 올바른 파라미터 애너테이션은 허용
- `throws`와 짧은 첫 인자의 불필요한 줄바꿈 복원
- 형식 적용을 두 번 실행해도 결과 동일
- 정상 스테이징 통과 및 잘못된 인덱스를 고친 작업 파일로 숨기는 경우 실패
