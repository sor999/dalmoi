# Spring Boot Backend Harness

## 적용 범위

상위 [공통 지침](../AGENTS.md)을 함께 따릅니다. 커밋·이슈·PR 및 GitHub 템플릿은 저장소 루트에서 공통으로 관리합니다. 아래 `docs/`, `.agents/` 경로는 별도 표시가 없으면 이 서버 폴더 기준입니다.

이 하네스가 위치한 Spring Boot 백엔드 프로젝트에 적용합니다. 프로젝트명, 도메인, 기본 패키지, Java·Spring Boot 버전, DB 및 인증 방식은 실제 소스와 빌드·설정 파일을 기준으로 확인합니다. 특정 서비스의 기능이나 인프라를 전제하지 않습니다.

## 작업 라우팅

- **Spring Boot 작업 진입점:** [Spring Boot Skill](.agents/skills/spring-boot/SKILL.md)을 확인합니다.
- **구현 및 설계:** [코드 컨벤션](docs/conventions/code-convention.md)을 따릅니다.
- **테스트:** [Test Skill](.agents/skills/test/SKILL.md)과 [테스트 컨벤션](docs/conventions/test-convention.md)을 따릅니다.
- **코드 리뷰:** [Review Skill](.agents/skills/review/SKILL.md)과 [코드 컨벤션](docs/conventions/code-convention.md)을 따릅니다.
- **이슈 작성:** [Issue Skill](../.agents/skills/issue/SKILL.md)을 따르고, 저장소에 이슈 템플릿이 있으면 사용합니다.
- **커밋 작성:** [Commit Skill](../.agents/skills/commit/SKILL.md)을 따릅니다.
- **PR 작성:** [PR Skill](../.agents/skills/pr/SKILL.md)을 따르고, 저장소에 PR 템플릿이 있으면 사용합니다.
- **배포 및 운영:** 저장소에 있는 배포 설정, 컨테이너 구성 및 CI/CD 워크플로를 확인합니다. 클라우드 제공자와 경로는 실제 프로젝트 구성을 따릅니다.
- **모니터링 및 관측성:** 프로젝트에 관측성 설정과 운영 가이드가 있으면 확인합니다.

## 작업 원칙

- 작업 시작 전 목표, 제약조건 및 완료 기준을 확인합니다.
- 변경사항과 관련된 기존 코드, 테스트 및 문서를 먼저 확인합니다.
- 기존 아키텍처와 프로젝트 컨벤션을 우선합니다.
- 현재 요구사항에 불필요한 계층, 추상화 및 의존성을 추가하지 않습니다.
- 관련 없는 코드와 사용자의 기존 변경사항을 임의로 수정하지 않습니다.
- 예외를 무시하거나 실패를 성공으로 위장하지 않습니다.

## 에이전트 협업

보조 에이전트를 사용하는 경우 다음 역할을 따릅니다. 사용 가능 여부와 위임 범위는 실행 환경 및 사용자 요청을 따릅니다.

- 메인 에이전트는 작업 계획, 구현, 통합 및 최종 검증을 책임집니다.
- Code Reviewer는 변경사항을 분석하고 문제점을 보고하며, 코드를 수정하지 않습니다.
- Tester는 테스트를 작성하고 실행하며, 프로덕션 코드를 임의로 수정하지 않습니다.
- 여러 에이전트가 동일한 파일을 동시에 수정하지 않도록 작업 범위를 구분합니다.
- PR 생성 및 GitHub 리뷰 코멘트 게시 등 외부 쓰기 작업은 사용자 요청에 따라 수행합니다.

## 검증 및 완료 기준

- 변경사항과 관련된 테스트를 우선 실행합니다.
- 필요하면 전체 테스트, 빌드 및 정적 검사를 수행합니다.
- 테스트 실패 시 구현 결함, 테스트 결함 및 환경 문제를 구분합니다.
- 테스트와 품질 검사를 통과시키기 위해 검증 조건을 완화하거나 우회하지 않습니다.
- 실행하지 않은 검증을 성공했다고 보고하지 않습니다.
- 작업 완료 시 변경 내용, 실행 명령어, 검증 결과, 미검증 항목 및 남은 위험을 보고합니다.
