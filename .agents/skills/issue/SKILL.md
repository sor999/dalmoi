프로젝트 이슈 템플릿을 활용한 제목, 본문 및 어투 작성 지침

# 이슈 작성

- Git 저장소 루트의 `.github/ISSUE_TEMPLATE/`에서 적합한 템플릿을 찾아 기존 구조 유지
- 템플릿이 없으면 아래 기능·TODO 항목으로 작성하며 존재하지 않는 경로를 전제하지 않음
- 외부 이슈 게시는 사용자 요청 범위에서만 수행
- 제목은 커밋 컨벤션에 따라 `타입: 작업 요약` 형식으로 작성
- 제목 예시: `feat: 주문 생성 기능 추가`
- 타입 뒤 괄호 사용 금지: `feat(주문): ...` 형식 사용 금지

# 라벨

- Android 변경사항을 다루는 이슈에는 `and` 라벨 적용
- 백엔드 변경사항을 다루는 이슈에는 `be` 라벨 적용
- Android와 백엔드 변경사항을 함께 다루면 두 라벨 모두 적용
- 기술별 지침과 컨벤션 문서 변경도 해당 영역에 포함하며, 공통 변경만 있는 경우 두 라벨을 임의 적용하지 않음
- 이슈 초안에는 적용할 라벨을 명시하고, 이슈 생성 및 수정 시 실제 라벨에 반영

# 작성 내용

- `✨ 구현할 기능`: 구현할 기능과 필요한 이유 작성
- `📝 TODO`: 구체적인 작업을 체크박스로 작성
- 요청에 없는 작업 임의 추가 금지

# 본문 구조

- 템플릿의 `##` 제목은 최상위 섹션으로 유지
- 각 `##` 섹션 안에 서로 다른 기능이나 작업 주제가 있으면 `###` 소제목으로 나누고, 관련 설명과 체크박스를 해당 소제목 아래 배치
- 소제목은 `### 인증 화면`, `### 코스 편집`처럼 내용을 바로 알 수 있는 구체적인 이름 사용
- 단일 주제나 짧은 항목만 있는 섹션은 불필요한 소제목 없이 작성

# 어투

- 간결한 개조식 및 명사형 종결 사용
- 목록은 하이픈 또는 체크박스로 통일하고 중단점(·) 혼용 금지
